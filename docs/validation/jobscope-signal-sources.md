# 信号来源采集与配置

## 使用入口

- 岗位研究 → 求职参考 → **按来源补数据**：勾选来源，点击「采集所选并重算」。每个来源显示状态、保存信号数和执行说明；失败不会阻断其他所选来源。
- 数据分析 → 公司横评 → **补数据来源**：先选信号来源，再用单公司 ↻ 或「一键补数据」。原有公告、公开网页、岗位和完整 JD 补读结束后，执行所选信号来源，再重算报告。
- 数据与采集 → 来源登记 → **信号来源与付费接口**：配置来源，查看最近一次信号采集的公司、时间、状态与说明。全部尝试保存在采集记录中。

保存配置不会发出接口请求。默认仅选择已启用、已接入且状态为 available 的免费来源，目前为「已保存岗位与证据」。官方公示页面仍待真实站点验证，需手动选择。付费 API 每次操作都要重新勾选；批量操作在启动时固定来源名单，对本批每家公司分别执行，结束后不沿用付费勾选。

「重新计算」使用已存材料及本地统计，不调用付费来源。信号采集时切换页面不取消已提交的来源队列，任务记录仍会保存，重算仍会完成。

## 来源状态与边界

| 来源 | 当前能力 |
| --- | --- |
| 已保存岗位与证据 | 本地统计，不联网；尊重开关 |
| 国家企业信用信息公示系统 | 浏览器采集入口已接入，可手动尝试；URL、页面结构、年报顺序及公司主体匹配仍需真实站点核验，不自动选择 |
| 信用中国 / 中国裁判文书网 | 未接入，不能启用或勾选 |
| 企查查 / 天眼查付费 API | 可配置的 HTTP GET 适配入口；需要用户自己的兼容接口或适配网关及额度 |

多平台检索中的 `qcc` / `tyc` 是公开网页快查。付费信号任务使用 `signal_qcc` / `signal_tyc`，本地信号为 `signal_jobscope_jobs`，收尾重算为 `reliability_compute`。两条路径各自独立。

`ready=true` 表示已实现、已启用且配置完整，**不代表真实接口已验证连通**。未实现或配置不完整的来源会返回明确原因。采集零信号、部分字段缺失、HTTP 失败与浏览器验证都如实记录。

## 付费接口格式

在来源配置中填写 URL、密钥和「请求格式与字段映射」：

- 密钥请求头默认 `Authorization`，前缀默认 `Bearer `（尾部有一个空格）。若接口使用 `token: <key>`，请求头填 `token`、前缀留空。
- 公司查询参数默认 `company`，可按文档改成 `keyword` 等名称。
- 字段映射是完整 JSON：规则 → 多个可选口径 → 槽位 → 候选字段名数组。保持规则和槽位名不变，仅按实际响应修改字段名。后端校验结构与槽位，字段缺失时不猜测数字。
- 示例：原有 `company_age` 映射为 `[{"founded_date":["establish_date","成立日期"]}]`；若接口实际返回 `founded_on`，可改为 `[{"founded_date":["founded_on"]}]`，同时保留其余规则的完整映射。
- 当前不自动生成厂商动态签名，也不支持 POST 取数；这类协议应由用户配置的适配网关转换。不可把预置候选字段当成已经核验的厂商协议。
- 密钥只写不读，存于本机数据库；改接口地址需重新填写密钥。关闭来源保留历史材料。

## 验证记录（2026-11-13）

所有功能测试使用临时目录，页面验收使用 8766。付费路径通过本地模拟 HTTP 服务验证，不调用真实付费接口：

- 配置自定义认证头、空前缀、自定义公司参数和响应字段后，实际请求成功，并保存可溯源成立日期信号。
- 返回缺少其他规则字段时显示 partial 与具体说明，而非宣称完整成功。
- 单次付费勾选在启动后清除；下次操作不会默认重复调用。
- 盘点已有资料会显示真实反馈，并自动刷新报告。
- 补数据任务默认排除付费和未验证来源；显式选择、关闭来源、异常收尾和逐来源独立失败由隔离测试覆盖。
- 前端异步回归检查覆盖切页后队列完成、付费勾选一次性消费、批量来源快照及历史读取失败不遮挡新报告。

真实公示系统及厂商采购接口仍需具备相应账号与授权后的人工验收；本地模拟成功不能替代真实站点协议验收。
