# JobScope 使用体验、可靠性与 Agent 实施计划

> **For agentic workers:** 使用 subagent-driven-development 分工，按下方复现和验收条件逐项实施。实施模型：GPT‑6.1 Sol。状态和实测结果记录在文末。

**目标：**从查看岗位到得到有依据的回答，原岗位、原问题和个人条件始终可找回。优先消除会丢记录、统计错或卡死的问题。

**实现方式：**沿用本地 FastAPI、SQLite、React/TypeScript 和现有流式事件，不新增基础设施；涉及旧数据的更改按需兼容，应用升级不要求重置数据库。各开发者负责不同文件或函数，主审负责接口对齐和集成验收。

| 顺序 | 工作包 | 具体实现 | 完成标准 |
|---|---|---|---|
| 1 | A：保护会话历史 | 在 `backend/jobscope/chat_runs.py`、`repository.py` 中替换重发前的破坏性截断。从早期消息重新生成采用可回看的新版本或新会话；保留范围与既有权限边界。将历史存档与模型输入截取分开。 | 建立 q1/a1/q2/a2；从 a1 重发，分别模拟失败、取消、成功，原会话的四条消息、引用不变，新结果可定位。101 轮后首轮仍可查。 |
| 2 | B：执行正确的筛选 | `backend/jobscope/research/query.py`、`tools.py`、`general_agent.py` 复用现有城市数据和已知地点；未解析的明确限制不能放宽为全库统计。返回实际采用的城市、金额口径和样本数。 | 同公司西安 12–18K、杭州 30–35K；各问当地至少 20K，分别得 0 和 1。含未知或不支持地点的提问得到澄清或明确限制；不得返回混入外地的统计。 |
| 3 | C：失败可恢复，首次提问不中断 | `frontend/src/chat/useChatRun.ts`、`ChatWorkspace.tsx`、`ChatComposer.tsx` 处理失败终态，暂停队列但允许修改/重试；未配模型也可输入。草稿按范围和会话隔离，提供进入模型设置并返回原处的入口。 | 本机模型失败后不再显示“生成中”，不用刷新可直接重试，失败轮提问不重复；离开设置再回来恢复原文；岗位 A 与岗位 B 不串草稿。 |
| 4 | D：保存个人劳动 | 在 `repository.py` 的岗位写入/更新拆开来源标签与个人标签；保留兼容的展示字段。检查收藏分页选择和星标请求晚到的处理。 | 同岗位重采两次、个人标签增删后再重采，收藏和个人标记稳定；两页各勾一家公司都能进入横评；快速切到 B，A 的收藏回包不覆盖 B 的详情。 |
| 5 | E：会话记得住条件，答案能核对 | 用户明确给出的城市、薪资或排除条件按会话保留，可更改、取消，并带入后续请求/工具筛选；遇到不支持的筛选要明说。顺序/合并两种展示使用一致的引用校验结果。 | 第五轮仍记得“杭州、至少 25K、不考虑外包”；换城市不清空薪资，取消薪资不会带回旧限制；新会话不继承另一会话偏好。未读取的证据编号在两种展示中均提示，不破坏普通面试/写作回答。 |
| 6 | F：让读岗位和做别的事不互相打断 | 在 `frontend/src/App.tsx` 和 `styles.css` 重排空库、已选岗位与对话状态：突出粘贴/外部查找，收起采集表单，提供显式的“问这份岗位 / 返回岗位”。浏览器采集独立忙碌，完成用可点击通知。摘要岗位支持在原档案补录有出处的完整职责。 | 1280×720 与 390px 宽能从导入走到提问再返回；普通点击不使页面跳栏。采集完成不抢页面、不锁简历保存；手动补全不冒充平台原文，保留原证据并能继续评估。 |

**依赖及顺序：**A/B/C 可并行；A 接着处理 D 的存储，B 接着处理 E 的检索与记忆，C 交付对话交互。D 的界面与 F 共用 App，由同一开发者接手；凡跨文件协作先约定接口。开发者先复现，再做最小修改，最后补通过/失败/取消或换范围的回归。

**验证：**开发、pytest、HTTP 验收禁止使用生产 `.data`。在 `backend` 下使用 `..\.venv\Scripts\python.exe -m pytest`，所有 app/Repository 使用绝对临时目录；运行本地模型失败和虚构岗位 UI 验收仅在显式独立数据目录的 8766 实例。前端做 TypeScript、Vite 构建；已有生产实例的 dist 与进程不作为试验场。默认不调用真实第三方服务、不推送发布。

**验收用例：**

1. 在测试库保存两份报价，分别以西安、杭州和未知地点提问；核对实际数据库筛选与工具返回，再检查模型接收的上下文。
2. 建两轮聊天，重发第一轮并模拟异常；查原会话完整性，打开重试结果，验证范围、草稿、队列和后续发送。
3. 对来源岗位做“编辑个人标签 → 重采 → 删除个人标签 → 重采”，对比两套标签和收藏；再对摘要岗位手动补入职责，检查证据和评估入口。
4. 在无模型、受控失败模型、窄屏、桌面四种状态走“导入 → 看详情 → 提问 → 去设置 → 返回”。另启动受控后台任务，验证完成时不跳走。

## 实施状态（2026-11-13）

**已完成。**A–F 六个工作包均已按计划实现：

- **A 会话历史**：从历史用户消息重发改为创建独立“修订”分支（`Repository.branch_for_edit`）；失败/取消不再截断或丢失消息。前端失败进入终态，可直接重试本轮问题。
- **B 检索筛选**：地点与金额条件从原始用户消息推导，城市字典和档案地点一起参与；未识别地点或年薪/到手口径返回澄清，不放宽为全库统计。`project_search` / `project_salary` 使用会话条件。
- **C 交互恢复**：未配置模型也可输入并保存草稿；提供“配置模型后发送”入口并返回原处。失败不残留“生成中”，排队消息跨刷新保留。
- **D 存储保留**：平台标签和个人标签拆分保存，旧 `tags` 自动迁移为个人标签；手动补录职责字段随重采保留。收藏跨页勾选按公司去重。
- **E 条件与引用**：会话详情返回当前条件；条件写入模型上下文和工具筛选；引用校验结果同时进入最终回答和时间线。
- **F 阅读与后台**：岗位阅读与岗位对话显式切换并恢复滚动位置；空库突出导入入口、采集表单收起；浏览器采集独立忙碌，完成用可点击通知；摘要岗位可在原档案补录有出处的完整职责并继续评估。
